# JLU-001 — Content Job List UX

Status: DONE — merged
Mode: SELF_REVIEW. Separate agent contexts were not used; no independent QA result is claimed.
Owner approval: 2026-10-02.
Objective: Make content jobs distinguishable without memorizing short IDs, and surface jobs that need user action first.

## Scope
- Flutter content queue presentation only.
- Make Idea the primary card label.
- Move short Job ID to secondary metadata.
- Replace machine-like status text with human-readable labels.
- Group/filter jobs by Action Required, Processing, Completed, and Backlog.
- Prioritize review, publish, and failed jobs ahead of passive states.
- Show a concise next-action cue on each card.

## Exclusions
- No backend/API/state-machine changes.
- No publish behavior changes.
- No new persistence.
- No redesign of Content Job detail page.

## Acceptance criteria and evidence
1. PASS: Idea is primary; short Job ID is secondary metadata in `home_page.dart`.
2. PASS: READY_FOR_REVIEW, READY_TO_PUBLISH, and failure states map to Action Required.
3. PASS: generating/asset/audio/render/publishing states map to Processing.
4. PASS: PUBLISHED maps to Completed; passive queue states map to Backlog.
5. PASS: status text uses human-readable labels.
6. PASS: Review and Publish jobs show explicit next-action cues.
7. PASS: existing search haystack still includes content ID, idea, status, format, and platform.
8. PASS: Flutter analyze, focused queue tests, existing Flutter tests, Android release APK build, and Graphify all passed on final head `c730f7fef9b54842a2670ddf9678153a791bd785`.
