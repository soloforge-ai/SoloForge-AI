# CJS-001 — Content Job Search / Filter UX

Status: BUILD_COMPLETE
Mode: SELF_REVIEW until an independent context is available.
Owner approval: 2026-10-02.
Objective: Make content jobs easier to find by idea, status, action, platform, format, and short ID without backend changes.

## Scope
- Improve existing Flutter queue search and filters only.
- Support multi-term search with AND semantics.
- Search human-readable status and action labels in addition to raw metadata.
- Keep search case-insensitive.
- Add visible Clear search control.
- Add counts to filter chips.
- Show filtered result count relative to total jobs.
- Add a one-tap Clear search & filters action for empty result states.

## Exclusions
- No backend/API changes.
- No new persistence.
- No new state-machine behavior.
- No pagination/server-side search.
- No redesign of Content Job detail page.

## Acceptance criteria
1. Search matches Idea, short Job ID, raw/human-readable status, next action, platform, and format.
2. Multiple search terms can match across different fields.
3. Search is case-insensitive.
4. Empty search matches all jobs in the selected filter.
5. Search can be cleared without manually deleting text.
6. Filter chips show current counts.
7. Queue header shows filtered count versus total when filtering/searching.
8. Empty results offer a one-tap Clear search & filters action.
9. Existing queue ordering/grouping remains unchanged.
10. Flutter analyze/tests and Android release APK build pass on final revision.
