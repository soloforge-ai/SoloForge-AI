# GTR-001 — Gemini Transient Error Handling

Status: BUILD_COMPLETE
Mode: SELF_REVIEW until an independent context is available.
Owner approval: 2026-10-02.
Objective: Make content generation resilient to temporary provider outages without retrying deterministic auth/model/config failures.

## Scope
- Content generation provider call path only.
- Retry transient HTTP statuses 429, 500, 502, 503, and 504.
- Use bounded retry attempts: maximum 3 attempts per provider.
- Use bounded backoff: 1 second, then 2 seconds.
- Preserve provider fallback after retries are exhausted.
- Preserve safe logging without API keys or response bodies.

## Exclusions
- No job state-machine changes.
- No provider priority changes.
- No new dependencies.
- No UI changes.
- No retry for 401, 403, or 404.

## Acceptance criteria
1. HTTP 503 retries and can recover on a later attempt.
2. HTTP 429 stops after exactly 3 attempts.
3. HTTP 404 does not retry.
4. Backoff sequence is exactly 1s then 2s for three attempts.
5. Provider fallback behavior remains available after retries exhaust.
6. Logs include provider, status, attempt, max attempts, and transient classification without secrets.
7. Existing content quality behavior remains unchanged.
8. Backend CI and focused tests pass on the final revision.
