# CQR-001 — Content Quality Review UI

Status: BUILD_COMPLETE
Mode: SELF_REVIEW until an independent context is available.
Owner approval: 2026-10-02.
Objective: Make the original idea, generated content, and semantic fidelity visible together before approval, and prevent approval of an explicit semantic FAIL.

## Scope
- Flutter Content Job detail presentation only.
- Add a Content Quality Review panel before generated draft fields.
- Show Original Idea and generated Hook/Caption together.
- Show semantic fidelity status, reason, required anchors, matched anchors, and generator provider/model when available.
- Block Approve when semantic fidelity metadata explicitly reports FAIL.
- Preserve approval for legacy jobs with no semantic fidelity metadata, while showing Not available and a manual-review note.

## Exclusions
- No backend/API/state-machine changes.
- No regeneration or publishing behavior changes.
- No new persistence.
- No changes to semantic scoring rules.

## Acceptance criteria
1. Original Idea and Generated Content are visible in one review panel before approval controls.
2. Semantic Fidelity PASS/FAIL/Not available is human-readable.
3. Required and matched anchors display when present.
4. Generator provider/model display when present.
5. Explicit semantic FAIL blocks Approve.
6. PASS does not block Approve.
7. Missing legacy metadata does not block Approve and is clearly labeled for manual review.
8. Malformed/missing anchor arrays do not crash presentation logic.
9. Flutter analyze and tests pass on the final revision.
